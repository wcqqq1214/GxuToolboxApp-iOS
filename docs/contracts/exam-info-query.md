## 1. 已确认的产品决策

| 编号 | 决策 | 行为边界 |
| --- | --- | --- |
| PD-01 | 刷新失败，继续展示当前账号的缓存 | 包括已成功确认的空快照；必须说明刷新失败或数据尚未更新，不能冒充本次查询成功 |
| PD-02 | 每轮刷新最多允许一次自动会话恢复 | 必要时最多重放一次考试查询；并发恢复应合并；预算耗尽后明确返回认证问题，不循环登录 |
| PD-03 | 网络成功但缓存写入失败，仍展示最新结果 | 独立表达持久化失败；数据库写入回滚；不能把它误报为网络获取失败 |

会话过期与账号退出是两件事：会话过期后，可以展示仍归属于当前账号的缓存；切换账号或显式退出后，立即停止展示旧账号数据。是否删除磁盘中的旧账号数据，由账号管理策略决定，本契约不以一次刷新失败作为删除依据。

## 2. 核心承诺与适用边界

> 一次成功的考试查询，代表取得当前账号、指定学期的完整且有效的考试数据。只有满足身份归属、范围、结构、完整性及请求有效性要求的结果，才允许替换该范围的持久化快照。

本版先规范“指定账号、指定学年和学期”的完整快照查询。

- 工具箱内部学期统一为 `1 | 2`。教务的 `3/12` 在教务接入边界转换；旧 UI 参数只在迁移适配入口转换一次。
- 学年使用起始年份，例如 `2025` 表示 2025—2026 学年；必须为有效整数。
- 新契约内部不使用 `""`、`undefined` 同时表示“全部”“尚未初始化”和“不筛选”。
- 后端现有“留空查询全部”的行为列为兼容行为。全部历史、整学年和分页查询必须另有明确的范围类型与写入规则，不能用它们替换某一学期的快照。
- 考试查询是只读业务。本文的自动恢复与查询重放规则不适用于评教提交等写操作。

| 编号 | 契约要求 |
| --- | --- |
| C-01 | 查询范围明确，账号、学年、逻辑学期及会话身份一致 |
| C-02 | 远端成功只返回有效的完整列表；`[]` 为真实空结果；失败不得伪装为成功值 |
| C-03 | 外部响应外壳、分页与记录都经过校验，合法缺失字段与解析错误分开 |
| C-04 | 错误有稳定分类，保留原因；缓存读写错误与远端错误分开 |
| C-05 | 认证由统一协调入口负责，遵守一次恢复预算和账号绑定 |
| C-06 | 快照按范围隔离，事务替换；空快照有元信息；失败保留原快照 |
| C-07 | 状态区分未查询、首次加载、刷新、成功为空、失败及持久化失败 |
| C-08 | 过期请求及失效会话不能覆盖缓存、认证状态或当前界面 |
| C-09 | 各层遵守第 9 节职责，消费者共享数据与刷新入口 |
| C-10 | 线协议和发布顺序支持新旧版本共存，旧响应的可信度不能凭客户端猜测 |

## 3. 数据与返回值契约

### 3.1 内部模型

以下 TypeScript 仅表达设计，不是已经新增的源码。正式落地时可按现有目录命名调整类型名，但不得改变语义。

```ts
type ExamScope = {
  system: "jw";
  accountId: string;
  year: number;
  term: 1 | 2;
};

type ExamRecord = {
  id: string;
  course: string;
  classroom: string | null;
  time: string | null;
  type: string | null;
  seat: string | null;
};

type ExamSnapshot = {
  scope: ExamScope;
  items: ExamRecord[];
  fetchedAt: number; // 客户端完成本次获取与校验的时刻，毫秒时间戳
};
```

- `id` 在同一查询范围内稳定、非空、唯一。缺失或重复不能静默覆盖；若外部系统确实不提供稳定标识，必须先制定并测试明确的生成规则。
- `course` 是必要的非空字段。其余字段未提供或为空时，在内部模型中统一为 `null`。
- `time` 保留校方原文。校方未提供时间与已有文本无法识别必须分别表达为展示状态 `tbd` 与 `unrecognized`；后者保留原文，不丢弃考试记录。
- 校园考试时间按 `Asia/Shanghai` 解释。开始、结束时间及 `upcoming/past` 在展示转换中计算，时钟可注入用于测试；前后台切换或时间跨界后应重新计算。
- `Dayjs`、`Moment`、渲染函数及随时间变化的状态不进入 API 数据模型或持久化快照。
- `fetchedAt` 不是校方更新时间，也不用于判定并发先后。旧字段 `updatedAt` 的秒级值只在迁移边界显式转换。
- `ExamScope.accountId` 是隔离标识，不是认证凭据。后端以会话识别请求者；客户端只可把响应归入与该会话可信绑定的账号，不能把请求参数中的学号当作身份验证。

### 3.2 各入口返回值

| 入口 | 返回与失败语义 | 允许的副作用 |
| --- | --- | --- |
| 远端查询 `fetchExams(query, sessionContext)` | `Promise<ExamRecord[]>`；成功包含 `[]`，失败抛分类错误 | 网络请求、响应校验与转换；不写缓存、不弹提示、不自行登录 |
| 本地读取 `readSnapshot(scope)` | `Promise<ExamSnapshot \| null>`；`null` 仅表示无可用快照；存储读取失败抛独立错误 | 读取和校验本地快照 |
| 本地提交 `replaceSnapshot(snapshot, commitContext)` | `Promise<void>`；成功表示事务提交；存储失败抛错，过期提交以内部取消信号结束 | 仅原子替换对应范围的记录及元信息 |
| 页面动作 `refresh()` | `Promise<void>`；正常完成表示本轮编排结束，成功与失败通过查询状态读取 | 编排认证、网络、缓存和状态；捕获预期错误，页面不再重复维护一套错误流程 |
| 展示转换 `deriveExamView(snapshot, now)` | 纯数据结果；不修改输入 | 无网络、认证、缓存或提示副作用 |

`null` 的许可位置是本地快照缺失和模型中明确允许缺失的字段。它不得表示远端解析失败、未登录或网络不可用。本地快照损坏或格式不兼容时，返回明确的缓存读取错误，不吞成未命中；迁移候选按第 12.1 节独立处理。

### 3.3 外部响应与完整性

后端必须先校验响应外壳，再读取 `items`。缺少必要字段、返回登录 HTML、收到未识别响应，均不得通过 `res?.items || []` 降为成功空列表。

只有外部协议中经过样本与测试确认的“无记录”表达，才能规范化为 `[]`。不得用宽泛的空值回退推断没有考试。

分页必须确认已取全：校验页码、总数及实际条数，必要时继续取后续页；中途失败、页码重复、分页元信息矛盾或无法确认取全时，整轮失败。设置较大的 `pageSize` 不构成完整性证明。完整性校验依据应由样本与测试锁定，不能仅以“当前考试通常很少”替代。

结构性错误、必要标识缺失和重复标识在本版采用整批失败策略，不返回删去坏记录后的“完整快照”。合法的未发布考场、座位、时间仍然允许缺失。

## 4. 线协议与兼容契约

### 4.1 成功响应

保留 `GET /jw/exam` 的既有成功信封和 `data` 数组形状。对明确指定学年、学期且符合新契约的请求，增加接口级元信息：

```json
{
  "code": 200,
  "message": "success",
  "data": [],
  "meta": {
    "contractVersion": 1,
    "complete": true,
    "scope": { "year": 2025, "term": 2 }
  }
}
```

- `meta` 只能在身份、范围、结构和完整性校验通过后生成，不能把字段存在当作实现了这些校验。
- `meta.scope` 必须与规范化后的请求范围一致；账号归属由认证上下文保证，不能靠回显客户端学号证明。
- `complete: true` 是该版本成功契约的一部分；不完整列表通过错误响应表达。
- 线协议继续兼容既有记录字段的字符串空值，以及可能缺失的 `seat`；客户端考试 API 转换为第 3 节的内部空值规则。直接将所有字段改为可空 JSON 值需要另行版本化，不能在兼容改造中暗改。
- `meta` 是本接口的附加信息，不要求其他接口同步更改。实现时避免被通用成功拦截器二次包裹。

该完整性标识用于避免一个已知问题：旧后端可能已经将异常响应转换成合法的 `[]`，客户端无法从这个数组恢复被丢弃的语义。

### 4.2 失败响应

保留 `code` 与 HTTP 状态一致的规则，新增稳定的可选原因标识，例如：

```json
{
  "code": 502,
  "reason": "JW_RESPONSE_INVALID",
  "message": "暂时无法更新考试安排",
  "data": null
}
```

`message` 用于展示，`reason` 用于分支。后端日志保留诊断原因；客户端不直接展示原始 HTML、堆栈、Cookie、密码或令牌。旧错误响应没有 `reason` 时，只按明确的 HTTP 语义进行兼容映射，不比较错误文案。

### 4.3 版本组合

| 客户端与后端组合 | 行为 |
| --- | --- |
| 旧客户端 + 新后端 | 成功仍是旧记录形状和数组，附加 `meta/reason` 不改变旧字段；解析失败改为真实失败响应 |
| 新客户端 + 新后端 | 校验版本、范围和完整性后，按本契约显示及提交快照 |
| 新客户端 + 旧后端 | 缺少可信版本或完整性信息时，返回 `CONTRACT_UNSUPPORTED`，保留本地快照，不执行整范围替换，也不显示本次成功为空 |

发布顺序为后端先具备契约能力，再发布依赖该能力的客户端。兼容行为在考试 API 边界实现，不直接改变 Web 全局 HTTP 拦截器的返回模式。

## 5. 错误分类与恢复契约

| 分类或原因 | 识别与归属 | 本轮处理 |
| --- | --- | --- |
| `INVALID_QUERY` | 输入不满足范围要求；后端对应 400 | 不发出非法请求，不读写其他范围 |
| `AUTH_REQUIRED / NO_ACCOUNT` | 初始化完成后确无账号 | 无法远端查询；引导配置账号，不伪装为空列表 |
| `AUTH_REQUIRED / SESSION_EXPIRED` | 明确的会话失效证据；后端对应 401 | 按第 6 节进行一次预算内恢复 |
| `ACCESS_DENIED` | 明确无权限；后端对应 403 | 不反复重登，不与会话过期混淆 |
| `NETWORK / TIMEOUT` | 客户端传输问题 | 保留数据；本版不做无限或隐式通用重试 |
| `UPSTREAM_UNAVAILABLE` | 校方不可用，或后端到校方的传输异常；后端通常对应 502/504 | 保留数据，允许用户后续重试 |
| `RESPONSE_INVALID` | 外壳、必要字段或模型不合法；后端来源异常对应 502 | 整轮失败，保留快照；客户端自身校验失败不篡改原 HTTP 状态 |
| `INCOMPLETE_RESULT` | 无法证明获取完整，或某页失败；后端对应 502 | 不提交部分列表 |
| `CONTRACT_UNSUPPORTED` | 响应缺少受支持的完整性契约 | 保留快照，不猜测可信度 |
| `CACHE_READ_FAILED` | repository 读取失败 | 独立记录，继续远端流程 |
| `CACHE_WRITE_FAILED` | repository 事务提交失败 | 展示网络结果，原磁盘快照回滚，状态标记未持久化 |
| 内部取消 | 请求被取代、会话代次失效或调用方取消 | 不提示用户，不发布旧结果 |
| `INTERNAL` | 未预期的程序异常 | 记录诊断并展示通用错误，不全部归为网络失败 |

客户端分类错误至少保留 `kind`、稳定的 `reason`、安全的 `message`；诊断用 `cause` 与可用的请求标识仅用于日志。错误原因不因跨越 hook/API 边界而被重新降为 `null` 或 `[]`。

## 6. 认证与身份契约

1. 本地账号初始化期间处于等待状态。`hydrating` 未结束前，不发布“没有账号”或“暂无考试”的结论。
2. 账号标识就绪后，先读取其本地快照；读取缓存不需要网络会话有效。
3. 查询编排从认证协调器获取当前账号的会话上下文，考试 API 只使用上下文，不自行验证密码、清 Cookie 或重登。
4. 可以优先使用现有会话发起查询。明确失效时交由协调器恢复，避免每个业务接口各自无条件调用一次探测请求。
5. 一轮刷新最多参与一次自动恢复。若查询前已恢复，之后的 401 不再开启第二次恢复；若首次查询遇到 401，恢复成功后最多重放一次。
6. 同一账号、同一有效会话上下文的并发恢复共享进行中的任务。不同账号不得复用同一个恢复结果；账号或凭据切换使旧恢复任务失效。
7. token 探测或登录遇到网络问题，应保留具体失败原因，不以此证明原会话已经过期。
8. App 只有在登录结果及所需域名间 Cookie 同步完成后，才能发布与该账号绑定的有效上下文。Web 通过现有登录入口建立等价绑定；Cookie 仍由浏览器管理，不要求复制 App 的凭据持久化方式。
9. Web 的会话失效与当前数据所属账号应分别维护。清空在线个人资料不能导致无法识别当前账号的离线快照；显式退出则立即清理当前展示引用和会话上下文。

同账号正常恢复产生新会话时，协调器可在同一轮刷新内更新查询使用的会话上下文，恢复预算不重置；必须确认账号、凭据和调用方查询代次均未变化。账号切换、退出或取消导致的失效不得通过这种更新重新激活。

身份绑定无法确认时，按认证或响应错误结束，不给数据补上当前学号后直接写入。

## 7. 缓存、并发与提交契约

### 7.1 快照生命周期

- 缓存隔离键包含 `system/accountId/year/term`；存储格式另带可识别的 schema 版本。
- 存在有效空快照时，读取结果必须是 `items: []` 的快照，不能返回缓存未命中。获取时间与版本需要独立于考试行保存。
- App 考试 repository 是考试数据的持久化权威入口。考试页和课表共同读取及订阅同一数据入口；课表只计算日程投影。MMKV 若保留，属于带来源版本的派生缓存，并可重建。
- Web 使用适合浏览器的存储适配，但遵守相同隔离、元信息、空快照和失败语义，不要求使用 App 的 SQLite 实现。
- 每次进入查询范围可先显示缓存，再后台刷新。离线缓存以更新时间及状态说明可信度；本版不增加未经确认的强制保留天数或自动删除策略。
- 替换事务同时处理该范围记录和快照元信息。记录所属账号、学期由外层 scope 确定，不能出现删除 A 范围、插入 B 范围的情况。
- 合法成功的 `[]` 清除原记录并写入新的空快照元信息。认证、网络、解析或完整性失败都不清除记录。
- 写入失败后，本轮网络快照仍进入共享内存数据入口；考试页和课表均可看到同一版最新数据，持久化状态标记为 `failed`。再次从磁盘加载旧数据不能悄悄覆盖这份较新的内存快照。

### 7.2 并发有效性

请求上下文至少表达账号/会话代次、查询范围及请求代次；这些值不是持久化账号键的一部分。

- 账号切换或退出使旧上下文失效。已失效的登录任务也不得把认证状态恢复为旧账号已登录。
- 调用方切换范围、取消或重新刷新后，被取代的请求不再提交结果。同一范围的旧请求晚到不能覆盖新结果。
- 同一范围的多个消费者通过共享查询入口合并刷新，或使用一致的范围代次，不能各自维护互不知情的最后写入者。
- 提交有效性检查必须与 repository 的提交控制协调，覆盖事务提交和共享内存发布。仅在 `setState` 前判断版本不满足契约。
- 若事务执行期间上下文失效，旧事务应回滚或被条件提交机制拒绝。已经先于切换合法完成的旧账号提交可以保留，但不能重新显示在新账号界面。
- Abort 仅用于节约资源；即使底层请求无法取消，以上检查仍必须成立。排序不得依赖可回拨的 `Date.now()`。

## 8. 页面状态与展示契约

| 情况 | 页面状态与操作 |
| --- | --- |
| 账号或范围尚未就绪 | 等待初始化，不显示成功空态 |
| 无快照，首次加载中 | 首次加载状态 |
| 有快照，远端刷新中 | 保持快照可见，显示刷新状态 |
| 成功获得非空列表 | 显示最新考试信息和本次获取时间 |
| 成功获得空列表 | 显示已成功确认的“本学期暂无考试安排” |
| 有快照，刷新失败 | 保持快照可见，说明本次未更新；按原因提供重试或登录入口 |
| 无快照，查询失败 | 错误状态，不显示“暂无考试” |
| 网络成功、写缓存失败 | 显示最新网络结果，说明尚未成功保存到本地 |
| 旧空快照，本次刷新失败 | 表达“上次查询暂无考试，本次未更新”，不能表述为刚刚成功查询为空 |
| 请求取消或已过期 | 不显示错误，也不恢复旧列表 |

查询状态应能表达 `snapshot`、首次加载、后台刷新、刷新错误及持久化状态。`snapshot === null` 与 `snapshot.items.length === 0` 不能等同；`refreshError` 与 `cacheWriteError` 不能等同。可以使用联合类型避免互相矛盾的组合，不强制使用这些字段名。

同一轮刷新由页面/展示反馈入口负责一次性提示。API、repository 和认证底层不弹 Toast 或 Alert。课表不支持定位的待定或未识别时间记录仍保留在考试列表中，不能因日程投影跳过它们就删除原始考试记录。

### 12.1 缓存迁移要求

1. 已有 SQLite 考试行带账号和学期，归属可确认时允许继续展示为旧版离线数据，并标明尚未按新契约校验；不得伪造为已通过新完整性校验的快照。使用明确的 `legacy/unverified` 过渡状态，与正式 `ExamSnapshot` 分开；旧记录更新时间不冒充完整快照的获取时间。
2. 旧 MMKV 考试缓存缺少账号归属。无法证明所属账号时，不将其直接绑定给当前账号，也不覆盖已有 SQLite 范围。先等待当前账号的可信刷新；清理只针对已识别的考试旧 key。
3. 数据迁移通过 Drizzle 生成 SQL、journal 和注册文件完成，不把历史删表逻辑扩展成迁移机制，不清空整个数据库。
4. 已有账号数据不为方便回滚而破坏。优先采用可兼容的附加元信息；若需回退，先停止新快照写入，保留旧数据。旧客户端再次写入后，不能让陈旧元信息继续证明快照可信，必须通过版本/一致性校验使其降级。

### 12.2 发布与回退要求

- S1 的后端可先发布，保持旧字段与数组形状；适配器的公开错误语义若改变，必须更新版本或使用新的严格解析入口，逐个迁移既有消费者。
- S2 及之后的新客户端上线前，确认生产接口提供约定的版本与完整性信息；回退到旧后端时，新客户端进入明确的不支持状态并保留缓存。
- 不以直接修改 Web 全局 HTTP 行为来完成考试迁移，避免把同一改动扩散到成绩、考勤等尚未迁移的 API。
- 修改通用认证核心时验证教务、考勤和统一认证现有适配器；一次恢复规则不能把需要验证码的流程改成无限无感重登。
- CI 可以先加入考试 parser、后端服务及客户端编排的定向检查。现有后端全套测试任务的恢复需要独立处理已存在的 mock 问题，不能把它已被注释误写成已有强制保障。

## 13. 验收场景

这些是后续需要实现的验收条件，本次未新增或执行这些测试。

| 编号 | 场景 | 必须观察到的结果 |
| --- | --- | --- |
| T01 | 非法学年/学期；旧 `3/12` 经过显式兼容入口 | 非法输入被拒绝；合法旧值只转换一次；新核心只接收 `1/2` |
| T02 | 完整合法的非空结果 | 展示新数据，原子替换对应范围，元信息与记录一致 |
| T03 | 完整合法的空结果，原先有考试 | 清除该范围原记录，仍保存并读取有效空快照和获取时间 |
| T04 | 旧后端返回成功 `null`，或校方缺少 `items`、返回登录页 | 转换为相应错误；不写入成功空快照，不清除原数据 |
| T05 | 必要标识缺失、重复或记录结构错误 | 整批失败；不静默丢记录或覆盖同 ID |
| T06 | 教务有多页数据 | 全部分页取得并校验后才发布成功及完整性标识 |
| T07 | 中间页失败、元信息矛盾或无法确认取全 | 整轮失败，不提交部分列表 |
| T08 | 缺失、不支持或范围不匹配的成功 `meta` | 明确错误，保留旧快照，不推断成功空态 |
| T09 | 无缓存与已确认空快照 | 读取结果和页面语义可区分；重启后仍可区分 |
| T10 | 缓存读取失败，网络成功 | 网络流程继续，最新结果可见，本地问题单独记录 |
| T11 | 网络成功、写缓存失败，包括远端有效空结果 | 最新结果在共享内存和页面可见；原磁盘事务回滚；标记未持久化 |
| T12 | 刷新失败，有/无快照及旧空快照三种情况 | 分别为保留数据、错误页面、上次为空但本次未更新；都不假装本次成功 |
| T13 | 账号初始化中、没有账号、明确会话失效 | 三种状态可区分；初始化中不误显示暂无或要求重新配置 |
| T14 | 并发查询需要恢复；恢复后重放仍为 401 | 同上下文共享恢复，一轮最多一次，失败后停止 |
| T15 | 会话探测或恢复遇到网络错误 | 保留真实原因，不能仅因网络失败证明会话失效 |
| T16 | 账号切换/退出后，旧查询或旧登录任务才返回 | 旧结果不写入失效上下文，不进入新账号页面或认证状态 |
| T17 | 同账号切学期，或同范围两轮请求乱序 | 被取代的请求不覆盖较新快照或当前列表 |
| T18 | 考试页、课表和下一事件同时消费或刷新 | 同范围使用共享刷新与同版数据；持久化失败时也一致显示内存新结果 |
| T19 | 事务执行期间查询或会话失效；外层 scope 与记录归属不一致 | 提交被拒绝或回滚，不混写范围；仅做 UI 版本判断不能使测试通过 |
| T20 | 旧 SQLite 与缺少账号信息的旧 MMKV 缓存 | SQLite 候选不伪装为新可信快照；匿名 MMKV 不绑定当前账号；不全库清理 |
| T21 | 时间未发布、格式无法识别、北京时间跨过结束时刻 | 状态分别正确，原文保留，动态状态更新；持久化没有日期库实例 |
| T22 | 旧客户端/新后端、新客户端/新后端、新客户端/旧后端 | 满足第 4.3 节三种组合，不发生双重信封或破坏性兼容回退 |
| T23 | 共享认证改造与部署依赖检查 | 教务、考勤、统一认证适配器回归；线上包与源码版本对应；错误日志不暴露凭据 |

建议的验证入口：adapters 使用现有 Vitest；后端服务使用现有 Jest 与 HTTP mock；App 编排与转换使用现有 Jest 配置和可注入时钟/存储；Web 按既有工具补充适配与状态验证。优先验证上述边界行为，不以页面快照测试代替身份、事务或分页验证。

## 14. 推广方式与维护约定

每个功能至少回答：查询范围是什么、成功代表什么、失败怎样表达、空结果是否可覆盖、认证由谁负责、缓存怎样提交、旧请求何时失效、页面如何降级。

| 推广对象 | 可以复用 | 必须另行明确 |
| --- | --- | --- |
| 已选课程 | 范围快照、账号隔离、刷新状态、认证协调 | 全部历史与指定学期的范围边界及完整性 |
| 成绩 | 错误分类、账号隔离、查询上下文、缓存展示 | 当前分页与全部成绩分开；单页不能覆盖完整成绩集合 |
| 考勤记录 | 认证边界、取消与乱序保护、存储适配约定 | 分页、增量、时间窗口及不同认证方式 |
| 课表 | 学期范围、共享查询入口、元信息 | 多来源合并、调课及各来源的更新规则 |
| 评教等写操作 | 安全错误信息、账号绑定、请求上下文 | 幂等性、提交确认、重复执行与恢复策略，单独制定写入契约 |

先完成考试的实际行为验证，再抽取至少两个功能已共享的稳定部分。共享类型与纯算法可跨 App/Web/后端；React/Vue 生命周期、Cookie 操作和存储驱动保留各平台适配。

本文件维护行为含义与设计理由；后续源码类型和 schema 表达形状，测试锁定行为。契约变更必须说明影响的调用方、兼容方式及对应验收项。运行现状继续通过差异清单更新，不能仅因文档发布就把 G 项标记为已解决，也不在多份工程说明中复制彼此不一致的规则。
