# iOS 迁移记录

构建与开发方式见[项目说明](../../README.md)和[仓库约定](../../AGENTS.md)，与 RN 上游的对齐差距和后端探测见[RN v2.2 差异表](rn-v2.2-gap.md)。所有具体行为以当前 Swift 源码和测试为准。

## 架构与界面约定

- **请求链路**：教务和考勤走自建后端代理，统一认证、物理实验、工程训练和 OA 由客户端直连；界面规范统一收口在 [GxuDesign](../../Packages/GxuDesign/README.md)。
- **导航与降级**：底部使用系统 `TabView`，iOS 26 保留液态玻璃且不随滚动收起，二级详情页自动隐藏标签栏；课表底部的日程附件在 iOS 18 降级为底部材质条。
- **沙盒权限**：模拟器使用 ad-hoc 签名验证 App Group 与 Keychain 行为；真机能力与签名要求见[设备检查清单](device-checklist.md)。

## 课表、调课与导出

- **学期参数与索引**：`/jw/schedule/personal`、`/jw/exam` 和 `/jw/score` 只接收逻辑学期 `1` 或 `2`（此前实测传 `term=3/12/16` 返回 HTTP 400），小学期只用于展示；不要把这个限制套到已选课程等其他路由。课表索引仅在课程、学期日期、校历、自定义课程或覆盖规则变化时重建，单纯更新同步时间直接复用。作息保留完整的 13 节，第 9、10 节只在显示层合并。
- **教务调课展示**：个人课表按教学班请求 `/jw/schedule/personal/reschedules`，只把「调」标在与现安排周次、星期、节次都匹配的课次上。缺失或空白字段显示「未提供」，不要当成沿用原安排；无原因或多条记录照常展示，旧缓存刷新个人课表后补全角标和教学班 ID。
- **本地调课**：支持调整当次（可跨周）或指定原周次的星期、节次和地点，按账号、学期和原课次存在本地并同步首页与小组件，刷新不丢失、可逐次还原。本地调课不写回教务也不改变考勤要求，改过时间的课次不再按新时段匹配考勤标记；原课次失效时不套用到其他课。
- **课表导出与原版教务网页**：「导出课表」只读当前账号、当前学期的本地缓存生成周课表图片（含自定义课程、冲突选择和本地调整），不触发刷新、重登或写入系统日历，保存相册只声明「仅添加照片」用途。「教务原版课表」运行在独立的临时网页会话中并注入当前账号教务 Cookie，新窗口沿用同一会话且不写入常规持久存储；「保存课表网页」导出的是 HTML 文件，需要联网与有效会话。

## 首页与日程调度

- **请求共用与节流**：首页与课表页共用在途的开学日期、个人课表和校园日历请求；自动刷新复用 2 分钟内的成功结果，手动刷新跳过有效期并合并同范围请求。
- **候选调度**：首页「接下来」和课表底栏共用候选逻辑。正在进行的考试和课程优先；待开始课程看今明两天，单独考试限未来 24 小时。假期提示直读完整校历（不受教学周范围或课表缓存限制），在学期日历时区（无课表时用系统时区）的 7 个自然日内显示倒计时，放假或寒暑假期间展示对应状态并让位于正在进行的课程和考试。

## 寒暑假与校历

节假日页面收录全国、地方和学校三类安排。内置校历对照[广西大学 2026—2027 学年校历](https://jwc.gxu.edu.cn/info/1322/3850.htm)补录了 2027 年寒假（1 月 18 日至 2 月 26 日）和暑假（7 月 12 日至 8 月 27 日），结束日取学生注册首日前一天（春季注册 2 月 27—28 日，秋季注册 8 月 28—29 日），不把教职工报到日算作学生假期结束日。

目前远端只下发调休数据，假期以内置校历为准（不会在客户端识别校历图片）；若以后远端提供 `holidays` 字段，则优先采用远端全量列表（即使显式返回空列表）。更新内置校历须核对学校原图，不按学期周数反推。

## 学业查询、登录与反馈

- **考试与日历**：Debug 构建可用 `-GxuDemo -GxuTab schedule -GxuScheduleSheet exam` 预览示例考试详情。工具箱「考试考场」和课表考试详情共用「添加到日历」，通过 [EventKitUI 用户确认流程](https://developer.apple.com/documentation/technotes/tn3153-adopting-api-changes-for-eventkit-in-ios-macos-and-watchos)预填课程、地点和提前 30 分钟提醒（不申请日历读取权限）；写入的是静态副本，后续变动须手动同步。
- **成绩、学年与绩点**：全学期请求拉完分页并校验完整性后按账号整库替换缓存（明确返回空才清旧成绩，分页失败保留可用缓存，重修前后均保留，缺学期记录归为「未标明学期」），同时校验会话和请求防止旧响应覆盖。共用学年选择器在十位学号指向更早入学年份时自动补齐转专业前学年，末年仍受学制和当前学年约束。绩点在当前筛选范围内按「课程名 + 学分」合并重修取最高分（同分取较新一条），依据《广西大学普通本科学生课程修读、考核及成绩管理办法（2019 年修订）》第三十八条（二），官方结果以教务处为准。
- **登录异常处理**：教务登录返回 HTTP 401 不一定代表密码错误（「无法获取初始登录 cookie」曾因客户端 User-Agent 不同触发），只有服务端明确拒绝凭据时才要求重登，其余失败保留账号状态。统一认证校验跟随 CAS 重定向，同时兼容 JSON 对象和数组。
- **意见反馈**：「全部反馈」请求免登录 `/feedback/public`（学号由服务端脱敏为前后各两位）；「我的反馈」使用 `/feedback/mine/{学号}`（不再请求会 401 的 `/feedback/{学号}`），仅在 `adminNote` 非空时标为「已回复」。按 `meta.totalPages` 分页，草稿按教务账号保存在本地并隔离会话，切号清空个人列表且不串用草稿。

## 隐私、凭据与使用统计

教务和考勤登录通过 HTTPS 将凭据发往 `api.tool.gxutech.xyz`，由第三方代理访问学校系统；OA、问卷和统一认证由客户端直连学校。凭据存在本机钥匙串以便自动重登，代理端是否留存无法从客户端代码判断。

设置里的「分享使用统计」默认关闭（老版本升级无偏好时同样关闭），每次上报应用启动或教务登录成功前都会检查该开关。开启后载荷只含事件名、功能、应用版本和固定占位 `userId: "0"`，不含学号或安装标识；因请求沿用现有后端会话，不能承诺网络层匿名或删除服务端历史记录，`PrivacyInfo.xcprivacy` 目前按保守口径声明。关闭后停止发新 `/event` 请求（已发出无法撤回），不影响业务和意见反馈。

## 后端不可用时的降级表现

`api.tool.gxutech.xyz` 与 `file.unde.site` 由第三方维护。服务不可用时，各页面保留缓存并提示错误，不清空页面也不阻塞启动；缓存读取或解码失败会在 `ErrorLog` 写入 `[cache]` 条目。

## 本地数据库容灾与备份

`gxu_tool.sqlite` 同时存着业务缓存与本地用户数据（自定义课程、冲突选择、评教模板）。每次以可写方式打开已有库前，都会先建主库及 `-wal`、`-shm`、`-journal` 的保护副本；打开或迁移失败时保留首次尝试前的副本供重试与重启使用，首次打开成功即删掉临时副本，而重试恢复成功时则将先前失败的副本移到同目录 `gxu_tool.sqlite.recovery-<UUID>`。快捷指令只用只读连接。打开在后台串行执行，失败日志只记错误域和错误码；失败期间 App 停在「本地数据恢复」页，等数据库就绪后再装配账号、首页、更新检查和小组件。

恢复页可将现场导出为二进制属性列表 `gxu-database-backup.plist`（版本 1 含 `formatVersion`、`createdAt` 和 `files` 原始字节，不含钥匙串且不联网）。保护副本未写完整时禁止可写打开；导出优先读取保护副本，且做二次校验读取，字节不一致即中止。这是故障现场的文件备份，不是 SQLite 在线备份 API 生成的健康快照，App 内暂未提供恢复导入且不能保证坏库一定可修；人工抢救时须留存原件并在独立目录用 `plistlib` 解包（将输出文件名限定为上述四个固定名称防路径穿越），检查 SQLite 完整性后再处理。

## 考试查询保留约束

以下约束沿袭自早期 RN 考试改造计划，用来指导后续开发与验收：

- 查询须绑定账号、学年和逻辑学期（`1` / `2`），全历史查询不能覆盖单学期快照。
- 响应须通过结构、范围和完整性校验才能替换快照，不能用空列表掩盖失败或擅自假定后端未提供的完整性保证。
- 缓存按账号与查询范围在事务内隔离替换，区分「空快照」和「未查询」；切号或退出后不得残留旧账号数据。
- 只读查询每轮最多自动重登重放一次且合并并发恢复，迟到响应不得覆盖新账号或新会话（此规则不适用于评教等写操作）。
- 写缓存失败时保留最新网络结果并单独提示持久化失败；待定时间记录保留在列表中，缓存协议升级须向后兼容。
