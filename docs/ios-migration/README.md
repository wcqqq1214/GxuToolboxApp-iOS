# iOS 迁移记录

构建与开发方式见[项目说明](../../README.md)和[仓库约定](../../AGENTS.md)，与 RN 上游的源码对照及后端探测结果见[RN v2.2 差异表](rn-v2.2-gap.md)。所有具体行为以当前 Swift 源码和测试为准；早期的迁移计划、提示词和交付日志都留在 Git 历史中，这里不再保留。

## 架构与界面约定

- **请求链路**：教务和考勤走现有的后端代理，统一认证、物理实验、工程训练和 OA 等未接入代理的功能由客户端直连。工具箱分组对照 RN v2.2，界面规范统一由 [GxuDesign](../../Packages/GxuDesign/README.md) 收口。
- **底部导航与降级**：底部使用系统 `TabView` 标签栏。iOS 26 保留液态玻璃效果且不随滚动收起，二级详情页自动隐藏标签栏；课表底部的日程附件在 iOS 26 使用系统底部附件，iOS 18 降级为底部材质条。
- **沙盒权限**：模拟器使用 ad-hoc 签名来验证 App Group 和 Keychain 行为；真机上的共享能力与签名要求见[设备检查清单](device-checklist.md)。

## 课表、调课与导出

### 学期参数与索引

- `/jw/schedule/personal`、`/jw/exam` 和 `/jw/score` 只接收逻辑学期 `1` 或 `2`（此前实测传 `term=3/12/16` 会返回 HTTP 400），小学期只用于展示；不要把这个限制套到已选课程等其他路由上。
- 课程、学期日期、校历内容、自定义课程或课程覆盖规则变化时，系统会重建课表索引；如果只有同步时间更新，就继续沿用已有索引。
- 节假日使用内置数据，远程 `data.json` 只下发调休安排。作息数据保留完整的 13 节，第 9、10 节只在界面显示层合并。

### 教务调课与本地调课

- **教务调课展示**：个人课表按教学班请求 `/jw/schedule/personal/reschedules`，只把「调」字标记贴在与现安排周次、星期、节次都匹配的课次上。详情页上下对照列出「调整前」和「调整后」的周次、星期、节次、地点和教师：调整后用强调色标题、确认图标和主文字色突出，调整前用次要文字色，同时保留调课类型、原因和类别。遇到缺漏或空白字段就直接显示「未提供」，不要当成沿用原安排；没有原因的记录照常显示，多条记录逐条展示。旧版缓存如果缺少角标或教学班 ID，刷新一次个人课表即可补全。
- **本地调课**：教务课程详情支持对「仅本次」或「指定原课次周次」修改星期、节次和地点，选「仅本次」时还可以跨周移动。修改结果按账号、学期和原课次保存在本地，刷新课表不会被冲掉，也可以逐次还原，并会同步反映在首页「接下来」和小组件里。本地调课不会写回教务系统，也不改变真实考勤要求，所以改过时间的课次不会按新时段匹配考勤标记；如果后续教务课表或校历调整导致原课次对不上，旧的本地调整不会套用到其他课次上。

### 课表图片导出与原版教务网页

- 工具箱和课表菜单里的「导出课表」只从当前账号、当前学期的本地缓存生成周课表图片，支持选周并通过系统分享面板保存或分享。整个过程不会刷新教务数据或要求重新登录，图片里会包含自定义课程、冲突选择和本地调课，没有缓存时会提示先去个人课表同步。这个入口不会向系统日历写入事件；保存到相册时只声明了「仅添加照片」用途，不读取相册。
- 图片导出页和班级课表页都提供「教务原版课表」入口，用于浏览个人与班级课表网页。网页跑在独立的临时会话里，打开时注入当前账号的教务 Cookie，跳出的新窗口也沿用这一会话，不会把 Cookie 写入常规网页的持久存储。登录失效时可以在页内重新连接，网络错误与 HTTP 错误分别提示；「保存课表网页」保存的是 HTML 文件，不是图片或日历事件，需要联网和有效的教务会话。

## 首页与日程调度

- **刷新与缓存复用**：首页随课表、考试和实验缓存更新，切换标签页时沿用当前快照。同一账号会话内，启动时共用首次缓存读取；短时间切回前台且缓存未变时沿用快照，已有快照时则在刷新收尾一并读取课表、校历和考试，而自定义课程、冲突选择或实验缓存变更仍会立即刷新。首页与课表页共用在途的开学日期、个人课表和校园日历请求：自动刷新复用 2 分钟内的成功结果，手动刷新跳过这个有效期，但仍合并已经在途的同范围请求。
- **日程候选规则**：首页「接下来」和课表底栏共用同一套候选逻辑。正在进行的考试和课程优先级最高；待开始的课程只取今天和明天，单独的考试候选限未来 24 小时内，都没有时隐藏提示。假期候选直接读取完整校历，不受教学周范围或课表缓存是否就绪影响；假期倒计时只在学期日历所在时区（无课表时使用系统时区）的 7 个自然日内显示，假期首日至末日显示放假状态，寒暑假则显示「寒假中」或「暑假中」，仍让位于正在进行的课程和考试。「节假日」页面照常展示全年列表。

## 寒暑假与校历

节假日页面收录全国、地方和学校三类安排。内置校历对照[广西大学 2026—2027 学年校历](https://jwc.gxu.edu.cn/info/1322/3850.htm)补录了 2027 年寒假（1 月 18 日至 2 月 26 日）和暑假（7 月 12 日至 8 月 27 日），归入「学校」分类。起始日取自校历寒暑假区域，结束日定为学生注册首日的前一天（春季注册为 2 月 27—28 日，秋季注册为 8 月 28—29 日），不把教职工报到日算作学生假期结束日。

目前远端配置只下发调休数据，假期仍以内置校历为主，客户端不会在运行时识别校历图片。如果以后远端开始下发 `holidays` 字段，会优先采用远端返回的完整列表（即使明确返回空列表也照用）。日后更新内置校历必须核对学校官方原图，不要根据学期周数推算；页面里也提供了校历原文链接。

## 考试、成绩、登录与反馈

- **考试详情与日历写入**：课表中的考试详情会显示考试类别和随时间变化的状态，3 天内的待考及正在进行的考试用红色提醒，已结束的场次标题变灰；未公布考场或座位时提示待定，支持选中考场文字或复制全部信息。Debug 构建可用启动参数 `-GxuDemo -GxuTab schedule -GxuScheduleSheet exam` 查看示例考试。
  在工具箱「考试考场」和课表考试详情里，起止时间有效的考试都可以通过同一套入口「添加到日历」。系统编辑页会预填课程名、时间、考场和座位，默认提前 30 分钟提醒，由用户确认保存或取消。实现采用 [EventKitUI 的用户确认流程](https://developer.apple.com/documentation/technotes/tn3153-adopting-api-changes-for-eventkit-in-ios-macos-and-watchos)，不申请日历读取权限；写入的是当时安排的静态副本，后续变动需要手动修改。
- **成绩查询与绩点核算**：默认展示当前学期，也可切到「全部学期」按学期分组查看原始成绩，并按课程名或教师搜索。重修前后记录都会保留，缺少学期标记的记录单独归到「未标明学期」。请求成绩时会拉完全部分页并检查完整性，之后才更新缓存，「全部学期」按账号整库替换；只有明确返回空结果时才清理旧成绩，分页中途失败时保留可用缓存并提示错误。同时校验请求与登录会话，防止较早请求晚返回覆盖新数据。
  绩点计算会在当前筛选范围内把「课程名 + 学分」相同的重复修读记录合并，取最高分（同分取较新的一条），而成绩列表仍保留原始记录。该口径依据《广西大学普通本科学生课程修读、考核及成绩管理办法（2019 年修订）》第三十八条（二），原条文用于毕业审核，工具箱把它借用到当前选定范围，官方结果以教务处为准。
- **登录错误处理**：教务登录接口返回 HTTP 401 不一定代表密码错了。此前排查「无法获取初始登录 cookie」时，就出现过随客户端 User-Agent 不同而返回 401 的现象，具体原因还没摸清。因此只有服务端明确拒绝凭据时才要求重登，其他失败保留现有账号状态。统一认证校验则会跟随 CAS 重定向，同时兼容 JSON 对象和数组。
- **意见反馈与本地草稿**：「全部反馈」直接请求免登录的 `/feedback/public`（与 RN v2.2 一致），返回所有反馈和官方回复，学号由服务端脱敏为前后各两位；「我的反馈」改用 RN 在 2026-11-13 新增的 `/feedback/mine/{学号}`（需已保存教务账号，切号会清空个人列表），不再请求会返回 401 的 `/feedback/{学号}`。列表按响应里的 `meta.totalPages` 分页，从详情页返回时保留已加载的分页和滚动位置，下拉刷新才重置回第一页。
  未提交或提交失败的草稿按教务账号保存在本地（未登录单独存一份），退出页面不会丢失；提交期间锁定编辑，同一登录会话内重新打开页面沿用提交状态以免重复提交，成功后清除草稿并可直接跳转「我的反馈」。草稿与提交结果都绑定各自登录会话，切号不会带入别人的草稿，旧会话的回调也不会刷新新会话页面。

## 隐私、凭据与使用统计

教务和考勤登录通过 HTTPS 把凭据提交到 `api.tool.gxutech.xyz`，由第三方代理访问学校系统；OA、问卷和统一认证则由客户端直连对应学校站点。App 会把账号密码存在本机钥匙串里以便重新登录，但代理服务端是否留存凭据没法从客户端代码判断。

设置里的「分享使用统计」默认关闭，老版本升级后没有对应偏好值也维持关闭。偏好保存在共享配置里，每次准备上报应用启动或教务登录成功事件前都会检查这个开关；关闭后停止发起新的 `/event` 请求（已经发出去的无法撤回），且完全不影响登录、日常查询和用户主动提交的反馈。

开启后，事件载荷只包含事件名、功能、应用版本和后端要求的固定占位值 `userId: "0"`，不再附带学号或安装标识。由于统计请求仍沿用现有的后端会话，不能据此承诺网络层绝对匿名或删除历史记录；`PrivacyInfo.xcprivacy` 目前先保持保守声明，等核实服务端数据处理方式后再对照调整。

## 后端不可用时的降级表现

自建后端 `api.tool.gxutech.xyz` 和静态文件服务 `file.unde.site` 由第三方维护，地址硬编码在源码中。服务不可用时，各页面保留已有缓存并提示错误，不清空页面，也不阻塞启动。读取或解码缓存失败时，`ErrorLog` 会写入 `[cache]` 条目，方便排查。

## 本地数据库容灾与备份

`gxu_tool.sqlite` 同时存着可重新拉取的业务缓存，以及自定义课程、课表冲突选择、评教模板等只留在本地的用户数据。每次以可写方式打开已有数据库前，都会先建一份主文件和附属文件（`-wal`、`-shm`、`-journal`）的保护副本；打开或迁移一旦失败，就留住首次尝试前的副本，之后的重试和重启都沿用它。首次打开成功会删掉临时副本，而重试恢复成功时则会把先前失败留下的副本移到同目录的 `gxu_tool.sqlite.recovery-<UUID>`，留作人工排查。快捷指令只用只读连接查缓存。打开失败期间，App 会停在「本地数据恢复」页面提供重试和备份导出，等数据库真正就绪后再装配账号服务、加载首页、检查更新和同步小组件。

数据库打开在后台串行执行，不会并发重入；错误日志只记错误域和错误码，不写 SQL、绑定参数或原始数据。如果是设备未解锁或存储已满导致的打开失败，解锁或腾出空间后重试即可；若是迁移脚本本身的缺陷得等后续版本修复，损坏严重的文件则可能需要人工修复，不能指望 App 一定能把坏库修好。

恢复页面可以把现场通过系统文件导出器存成二进制属性列表 `gxu-database-backup.plist`。版本 1 包含 `formatVersion`、`createdAt` 和 `files`，其中 `files` 存了主库及存在的 `-wal`、`-shm`、`-journal` 四个文件的原始字节；导出不会碰钥匙串，也不会联网上传，由用户自己选择可信位置保存。只要保护副本没有完整写盘，App 就会中止可写打开；导出时优先读取保护副本，且只在源目录里做二次校验读取，一旦读失败或两次字节不一致就停止导出。

要注意，这只是故障现场的文件打包备份，不是通过 SQLite 在线备份 API 生成的健康快照，字节一致也不能保证损坏文件可修复。目前应用内还没有恢复导入入口；如果确实要人工抢救，先留好原备份文件，在独立目录里解包（Python 标准库 `plistlib` 可以读 `files`，但务必把文件名限制在上面那四个固定名字，防止路径穿越），做完 SQLite 完整性检查和修复后再处理，不要直接覆盖用户现有的数据库。

## 考试查询保留约束

下面这几条约束继承自早期 RN 考试改造计划，用来指导后续开发和验收，不代表现在的代码已经全部覆盖到位。

- 查询必须绑定账号、学年和逻辑学期（内部使用 `1` / `2`），全历史或整学年查询不能覆盖单学期快照。
- 响应必须经过结构、范围和完整性校验才能替换本地快照；空列表只能表示服务端明确确认没有记录，不能用空列表掩盖解析或网络错误，也不能由客户端擅自假定后端未提供的完整性保证。
- 缓存按账号和查询范围隔离，并在事务里替换，同时要能区分「空快照」和「未查询」。刷新失败保留当前账号缓存并提示原因；会话过期和主动退出分开处理，切号或退出后绝不能残留上一个账号的数据。
- 一轮只读查询最多自动恢复认证并重放一次，并发恢复应当合并；迟到的请求不能覆盖新账号、新会话、缓存或界面。这条重放规则不适用于评教提交等写操作。
- 网络查询成功但本地写缓存失败时，界面应保留最新的网络结果并单独提示持久化失败，同时清晰区分未查询、加载中、刷新中、结果为空、请求失败和缓存写入失败这几种状态。
- 考试列表、课表和首页共享数据源和刷新入口，无法投影到课表格子里的待定时间记录仍保留在列表里。缓存协议升级时做好向后兼容，不能把旧版缓存当成已通过新契约校验的快照。
