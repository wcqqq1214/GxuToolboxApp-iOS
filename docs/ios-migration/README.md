# iOS 迁移记录

当前构建与开发方式见[项目说明](../../README.md)及[仓库约定](../../AGENTS.md)。[RN v2.2 差距表](rn-v2.2-gap.md)记录迁移时的对照；当前行为以 Swift 源码和测试为准。旧迁移计划、提示词和交付日志可在 Git 历史中查阅。

## 保留的迁移决策

- 教务和考勤优先使用已提供的后端代理；统一认证、实验课、OA 等未覆盖的功能按需直连。工具箱分组与功能以 RN v2.2 对照，界面按 [GxuDesign](../../Packages/GxuDesign/README.md) 设计。
- 个人课表按教学班查询 `/jw/schedule/personal/reschedules`，只在匹配现安排周次、星期和节次的课次上显示「调」。对应课次的详情显示该次调课的原因和类别。旧课表缓存缺少标记和教学班 ID 时，刷新个人课表后即可读取新字段。
- `/jw/schedule/personal`、`/jw/exam`、`/jw/score` 用逻辑学期 1 / 2。迁移时实测 `term=3/12/16` 返回 400；小学期仍可用于展示。不要把这个限制套到已选课程等其他路由。
- 教务登录的 HTTP 401 不一定是凭据错误。例如「无法获取初始登录 cookie」曾随客户端 User-Agent 不同而出现，原因未证实。只有服务端明确拒绝凭据时才要求重新登录；其他失败保留账号状态。统一认证校验跟随 CAS 重定向，接受 JSON 对象或数组。
- 绩点计算在所选范围内按「课程名 + 学分」合并重复修读，取最高成绩，同分取较新的记录；成绩查询仍显示原始记录。依据为《广西大学普通本科学生课程修读、考核及成绩管理办法（2019 年修订）》第三十八条（二）；原条款针对毕业审核，工具箱把规则用于所选范围，官方结果以教务处为准。
- 节假日使用内置数据，远程 `data.json` 用于调课；作息保留原始 13 节，第 9、10 节只在显示层合并。模拟器使用 ad-hoc 签名验证 App Group 和 Keychain，真机共享能力见[设备检查清单](device-checklist.md)。
- 首页随课表、考试和实验缓存提交更新，切换标签沿用当前快照。同一账号会话内，启动时共用首次缓存读取，短时间回前台且缓存未变时沿用快照。已有快照时，课表、校历和考试在刷新收尾时一起读取。自定义课程、冲突选择和实验缓存变更仍会立即触发读取。首页与课表共用在途的开学日期、个人课表及校园日历请求。自动刷新复用两分钟内的成功结果，手动刷新跳过这段有效期。已在途的同范围请求仍可共用。
- 首页「接下来」和课表底栏共用日程候选逻辑。正在进行的考试、课程优先；课程候选只取今天和明天，单独的考试候选限未来 24 小时内。假期候选直接读取完整校历，不受教学周范围或课表缓存是否存在限制。假期倒计时仅在学期日历时区（没有课表时使用系统时区）的 7 个自然日内显示，假期首日至末日显示放假状态，寒暑假显示“寒假中”或“暑假中”；正在进行的课程、考试仍优先。无近期候选时隐藏提示；「节假日」页面仍展示完整列表。
- 底部导航使用系统 `TabView` 标签栏，iOS 26 保留液态玻璃效果，并固定为不随滚动收起。详情页隐藏标签栏，返回后恢复。日程附件仅显示在课表页，iOS 26 使用系统底部附件，iOS 18 降级为底部材质条。
- 课表索引在课程、学期日期、校历内容、自定义课程或课程覆盖规则变更时重建。仅同步时间变更时，继续使用已有索引。

## 登录信息与使用统计

教务和考勤登录通过 HTTPS 向 `api.tool.gxutech.xyz` 提交凭据，由第三方代理访问学校系统。OA、问卷和统一认证直接访问对应学校系统。客户端将账号密码保存在本机钥匙串，用于登录流程；客户端源码不能证明代理服务器是否留存凭据。

设置页的“分享使用统计”默认关闭，旧安装没有偏好值时也保持关闭。偏好保存在共享配置中，应用启动事件和教务登录成功事件均在发送前检查该值。关闭后不再发起新的 `/event` 请求，已经发出的请求无法撤回。开关不影响登录、业务请求或用户主动提交的反馈。

启用后的事件正文只包含事件名、功能、应用版本和兼容后端的固定 `userId: "0"`，不再填入学号，也不生成安装标识。统计仍使用现有后端会话，不能据此承诺网络层匿名或删除服务器上的历史数据。隐私清单暂保留保守声明，后续结合服务端的数据处理方式核实。

## 数据库打开失败

本地数据库 `gxu_tool.sqlite` 同时保存可重新获取的缓存和自定义课程、课表冲突选择、评教模板等用户数据。已有数据库在可写打开前会保全主文件和附属文件。打开或迁移失败后保留第一次尝试前的副本，重试和重新启动都沿用该副本。首次打开成功后清理临时副本。重试成功后，把先前失败保留的副本移入同目录的 `gxu_tool.sqlite.recovery-<UUID>`，以便后续人工检查。快捷指令用只读连接查询缓存。应用显示“本地数据恢复”页面，允许重试和导出原始数据备份。数据库成功打开后才装配账号服务、加载首页、检查更新及启动小组件同步。

数据库打开在后台执行，重复打开请求不会并行执行。失败日志只记录错误域和代码，不记录 SQL、绑定参数或原始数据。用户可以在解锁设备或释放存储空间后重试；迁移缺陷需要通过后续版本修复，损坏文件可能需要进一步人工恢复。应用不会保证损坏数据一定能够修复。

备份通过系统文件导出器保存为二进制属性列表 `gxu-database-backup.plist`。版本 1 包含 `formatVersion`、`createdAt` 和 `files`；`files` 保存数据库及存在的 `-wal`、`-shm`、`-journal` 文件的原始字节。导出不会读取钥匙串或上传文件。备份包含个人数据，用户自行选择可信的保存位置。保全副本未能完整写入磁盘时，应用停止可写打开。恢复页优先导出保全副本。导出只读取源目录，读取失败或两次读取结果不同会停止导出。

这是故障现场的文件备份，不是通过 SQLite 在线备份接口生成的已验证快照。保全副本通过逐文件复制和比对生成；字节一致也不能证明损坏文件可恢复。尚未提供应用内导入入口。人工检查时先保留备份原件，在独立目录解包副本，再根据 SQLite 完整性检查结果处理，不能直接覆盖用户现有数据库。Python 标准库 `plistlib` 可读取此格式，`files` 的每个值是对应文件的字节。文件名须限制为上述四种名称，避免把不可信备份的路径写入任意位置。

### 寒暑假数据

节假日入口包含全国、地方和学校假期。内置校历根据[广西大学 2026—2027 学年校历](https://jwc.gxu.edu.cn/info/1322/3850.htm)补充 2027 年寒假（1 月 18 日至 2 月 26 日）和暑假（7 月 12 日至 8 月 27 日），归入“学校”。起始日来自校历寒暑假区域，结束日采用学生注册首日前一天：春季注册为 2 月 27—28 日，秋季注册为 8 月 28—29 日。教职工报到日不作为学生假期结束日。

当前远端数据只提供调休，假期使用内置数据；这不是运行时自动识别校历图片。后续远端提供 holidays 时仍优先采用远端完整列表，包括显式空列表。更新校历时须核对学校原图，不从学期周数推算寒暑假。页面提供校历原文链接。
